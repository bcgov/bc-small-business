This guide provides step-by-step instructions for performing the annual update of the BC Small Business Profile dashboard. 
It covers code updates, configuration, publishing, and data management tasks to ensure the dashboard remains accurate and up to date.

## Code Update Steps:

### 1. Clone the Repository
- Create a new branch for the annual update
- Clone the repo
- Switch to the new branch in your local environment

### 2. Configure Settings
- Create a `config.yml` file in the root folder to set:
  - Location of the Excel data (excel data generated by the BETS team at BC Stats)
  - Google Analytics (GA) tracking ID linked to BC Stats
- Example:
  ```yaml
  default:
    lan: <lan path information>
    data_filename: <excel file path information>
    ga_tracking_id: <google analytics tracking information>
  ```

### 3. Convert Excel to CSV
- Update the year at the top of `R/convert_to_csv.R` and modify if Excel format changed.
- Run `R/convert_to_csv.R`:
  - Creates RDS data for the app (`app/data/data_new.rds`)
  - Creates CSV data and CSV appendix data for the BC Data Catalogue (saved to root folder)
- Save CSV files on LAN:  
  `Small Business Profile\Annual <year>\Data\For BC Data Catalogue`

### 4. Generate Geo Data
- Run `R/get_geo_data.R` to create spatial data for the economic regions map.

### 5. Add Google Analytics Tracking
- Run `R/generate_ga_tracking_code.R`:
  - Adds GA tracking code to `app/www/google-analytics.html` using IDs in `config.yml`.
- To disable GA tracking:
  - Set `google_tracking = FALSE` in `app/R/global.R`.
- To add extra GA IDs:
  - Add them in `config.yml` and update `R/generate_ga_tracking_code.R` accordingly.

### 6. Update Downloadable Excel Files
- Copy new Excel file from LAN to `app/data`.
- Copy previous versions from LAN to `app/data`.
- In `app/app.R`:
  - Add previous year’s download button in UI under “Previous Versions”.
  - Update new download button in Server to reference the current year.

### 7. Update Highlights
- Open `app/R/faux_highlight_text.R` and save as `app/R/highlights.R`.
- Add new highlights text to `highlights.R`.
- **Important:** Highlights must not be pushed to GitHub until cleared for release.  
- **Important:** Files in `app/R` run alphabetically at startup; ensure `highlights.R` overwrites placeholder text.

### 8. Update Additional Support Files
- `app/fig_code/figure_notes.R` – figure definitions, sources, notes.
- `app/R/keywords.R` – search term to figure linkage.

### 9. Update Metadata
- Update `last_updated` date in `app/R/global.R`.

## Publish Steps:

**Note:** The following publish steps are not strictly chronological. Complete them as appropriate for your workflow.

### Push changes to GitHub
- Create PR → Request review → Merge to main → Create release.

### Publish app
- **Testing:** `sb-profile-test`
- **Production:** `sb-profile`

### Save final code/data to LAN
- Download app bundle from shinyapps.io and save on LAN:  
  `Small Business Profile\Annual <year>\dashboard code and data - <year>.zip`  
  (Extract `.tar` if needed and compress as `.zip`.)

### Update BC Data Catalogue
- Update the BC Data Catalogue data with the CSV data generated by `R/convert_to_csv.R`:  
  https://catalogue.data.gov.bc.ca/dataset/bc-small-business-profile

### Tip: Publishing from Test to Production Using the Bundle

If the test site (`sb-profile-test`) is complete and awaiting sign-off, you can publish it to production without re-running the update steps. This ensures consistency between environments.

#### Steps:
1. **Download the bundle**  
   - Go to https://www.shinyapps.io and download the app bundle for `sb-profile-test`.

2. **Extract the `.tar` file**  
   - Unzip the downloaded file and extract the `.tar` archive.

3. **Prepare the R project**  
   - Create a new R project locally.
   - Inside the project, create an `app` folder.
   - Copy the following from the extracted bundle into the `app` folder:
     - `data/`
     - `fig_code/`
     - `R/`
     - `www/`
     - `app.R`

4. **Open in RStudio**  
   - Open the R project in RStudio.
   - Confirm that the app runs locally by clicking **Run App**.

5. **Publish to Production**  
   - Use the **Publish** button in RStudio to deploy the app to `sb-profile` (production environment).
   - Ensure you select the correct account and application name during publishing.

> **Important:** This method guarantees that the production app matches the tested version exactly, even if the original developer is unavailable.
